# PBI-021: Task deep-link surface (ContradictionBadge href)

## Directive

`ContradictionBadge` today renders as a span: no `/tasks` route and no
tasks read-model router exist, and the claims view returns no task id,
so an href would be a dead promise (PBI-017 review). To honor Tech Spec
§9.2 ("links directly to the targeted-research task if one exists"):
add a minimal tasks read surface (by claim — e.g. `GET .../tasks`
filterable by claim, reusing the `T-<claim-id>` convention where
possible but NOT relying on it), then wire the badge href to it. The
badge must degrade back to a span when no task exists for the claim.

## Context

- Spec: `specs/phase-1-mvp/spec.md` (claims UI), Tech Spec §9.2
- Depends on: PBI-017
- Files/modules touched: `backend/app/api/` (tasks router or claims
  extension), `frontend/src/components/ContradictionBadge.tsx`,
  frontend tests
- Plane: none

## Verification

- Badge with an existing task renders a working link; without one it
  renders the current span. Backend + frontend gates green.

## Refinement rule

- If reality diverges from the spec: stop, flag for human review.
