# PBI-010: Tool-output cache (check-before-fetch)

## Directive

Implement `backend/app/tools/cache.py` per guide §4.3: SHA-256 URL/DOI
hash keys under `<project>/tool_outputs/`, every fetch path routes
through `cached_fetch`, cache-hit returns file content without network.
Tests prove: first call fetches, second call hits cache (fetch fn
called once), and pre-seeded cache files are honored. Wire the cache
into the PBI-009 fetch tools at the SAME public names (`fetch_url`,
`fetch_pdf`) or explicitly ban direct raw imports — otherwise a future
graph/agent author bypasses the cache by importing from
`app.tools.fetch` (PBI-009 review).

## Context

- Spec: `specs/phase-1-mvp/spec.md`
- Depends on: PBI-009
- Files/modules touched: `backend/app/tools/cache.py`,
  `backend/app/tools/fetch.py` (route through cache),
  `backend/tests/test_cache.py`
- Plane: none

## Verification

- Spec `Contracts` (cache-reuse clause): double-fetch test asserts a
  single underlying call; cache dir layout matches spec
  (`tool_outputs/<session_id>/`).
- Gate: `python -m pytest backend/tests -q` green.

## Refinement rule

- If reality diverges from the spec: stop, flag for human review.
  Any fetch bypassing the cache is a contract violation.
