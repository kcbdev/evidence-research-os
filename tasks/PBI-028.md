# PBI-028: Per-project model settings UI

## Directive

Live-fire follow-up: UI-created projects get fail-closed
`openrouter/auto` model defaults (correct — runs refuse until
configured), but NOTHING in the UI configures them, so Start-run
fails with a refusal the user cannot resolve in-app. Two surfaces,
one PATCH:
1. Creation form REQUIRES model selection (council scientist /
   investigator / skeptic + judge; empty submit blocked with a
   message — no silent auto defaults in the UI).
2. Overview gets a Settings tab (current values prefilled) for later
   edits.
Both persist via a new `PATCH /api/v1/lab-projects/{id}` endpoint
that updates ONLY the model assignment through `store.write_meta`
(committed; judge overlap refused with a readable 400 the UI
surfaces verbatim per the api.ts error-body fix). Backend keeps
auto/auto + refusal as the backstop for direct API callers. Tests:
endpoint validation + refusal + unknown-project cases; UI tests for
required-create, settings save + refresh, refusal surfacing.
