# PBI-069: Builder tabs (Roles/Tools/Budget/Metadata) + retire YAML-editor route

## Directive

Fill the four non-canvas tabs and close the two-surfaces problem.
Roles tab: Table of role slot × assigned model reusing
`ModelCombobox`, with the same judge/council-overlap live validation
as Settings → Models surfaced inline (red row highlight + Tooltip
explaining why, not just on save). Tools tab: Checkbox grid grouped
by tool category for methodology-global enables, with header text
stating role nodes may restrict but never expand the set. Budget tab:
plain `Form` (max_model_calls, max_research_rounds, max_sources,
max_sources_per_claim) with min/max number Inputs pre-filled from
Settings → Budget defaults. Metadata tab: Name, Description
Textarea, Compatible-modes multi-Select (research/brainstorm/
academic). Then retire the raw-YAML `[id]` route from PBI-057: list
page "Edit" opens `/builder` directly and the old `[id]` path
redirects to `/builder` (redirect preferred over deletion so booked
URLs keep working) — exactly one edit surface remains; Export/Import
YAML (PBI-070) is the raw-text escape hatch. All tabs read/write
through the same `methodology-graph.ts` state + methodology API as
the canvas (no second save path).
