# PBI-022: Retry transient model failures (don't fail runs on hiccups)

## Directive

Live-fire (PBI-019) proved a single transient empty completion
(`content=None` from a healthy model, verified working 60s later)
kills a 10-minute run: `asyncio.gather` in `independent_first_pass`
raises on the first failure, the PBI-008 fail-fast fires, the run
goes `failed`. Detection is correct; recovery is absent. Implement
bounded retry in `call_model` (or a thin wrapper at the call sites):
retry on `None`/empty content and on transport errors
(`httpx.TimeoutException`, 5xx, 429), max 3 attempts with backoff,
then raise the current loud errors. Deterministic (mocked) tests must
prove: (1) transient-then-success returns content with N calls made
(budget counts RETRIES as calls — no free calls); (2) persistent
failure still raises after exactly max attempts; (3) the PBI-008
`ValueError`/`RuntimeError` semantics are preserved post-retries.

## Refinement rule

- If reality diverges from the spec: stop, flag for human review.

  (same family as unbounded graph loops).
