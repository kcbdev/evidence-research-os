# PBI-083: Structure editor before final synthesis

## Directive

Adopt the extraction doc's structure-editor row (UX): an optional
manual step on the Output view — select which claims go in which report
section and in what order — before `synthesis` writes prose. Purely an
ordering/inclusion UI, not a content editor: claim statements are never
edited here. The order persists as a run artifact (same treatment as
`plan/` per ADR-0001, not an evidence object), and the synthesis node reads
it when present, falling back to current behavior when absent. No compiler
or storage-layer redesign; if honoring the order requires either, stop per
the refinement rule.

## Context

- Spec: `specs/phase-6-analog-enhancements/spec.md` (C11)
- Depends on: PBI-076 (same-file chain on `nodes.py` synthesis area —
  sequenced, never parallel)
- Plane: `kcb/EVRSH-72`
- Files/modules touched: `backend/app/graph/nodes.py` (synthesis input
  only), Output view + structure editor UI, backend + frontend tests

## Verification

- Spec contract C11: fixture section order is honored verbatim in the
  synthesis input by test; absent order file reproduces legacy behavior
  exactly; UI pins reorder/select with no statement editing affordance.
- Executable: backend halves + frontend typecheck/suite/build green.

## Refinement rule

- If reality diverges from the spec: stop, flag for human review.
