# PBI-068: Condition Builder + loop-back edges

## Directive

Add looping to the canvas — the most complex single piece, built last
per the spec's ordering. A dedicated second (distinctly styled, bottom)
handle on loop-capable nodes: dragging from it always creates a dashed
amber edge and immediately opens the `ConditionBuilder` (in the Node
Inspector Sheet, and on dashed-edge selection). Builder UI: "Repeat
this stage while:" rows of Field-Comobox (populated from `GET
/methodologies/condition-fields`) × Operator-Select (filtered by
field type: numeric fields never offer `contains`; boolean fields get
`is true`/`is false`) × Value-Input (type-matched: number input for
counts, Switch for booleans), "+ AND" appending rows (AND-chaining
only — no OR/nested groups in v1), compiling client-side to the
`simpleeval` string stored as the stage's `loop_condition`
(coexisting with registry `loop_while`, never both on one stage —
two set is a validation error, per the methodology model). Collapsed
"Advanced: edit as expression" toggle reveals a minimal CodeMirror
textarea pre-filled with the compiled string; direct edits round-trip
back into the no-code rows while still matching a simple
single/AND-chain pattern, else the rows disable with the note "this
expression is too complex to edit visually — advanced mode only".
Unconditional back-edges (`loop_always`) and forward `route` branches
are out of scope here — stages needing them stay hand-editable via
Import/Export (PBI-070), and the canvas must not corrupt them on
load/save (unknown-to-canvas keys round-trip byte-identical).

## Waiver (human-approved 2026-09-13)

- Advanced editor is a shadcn monospace Textarea, not CodeMirror:
  the advanced input is a single-line `simpleeval` string (not
  JavaScript — `lang-javascript` would mis-highlight), and
  `@codemirror/view` alone buys nothing over a textarea. No new
  dependency. Revisit if multi-line expression editing ever needs it.

## Verification

- Spec contracts: rows compile to the expected `simpleeval` string
  (unit-tested: count/bool fields, two-row AND, operator filtering);
  a `loop_condition` authored in the builder alters branching on a
  real run (true → loop taken; false → falls through — same bar as
  the 5b Tier B contract); advanced-mode complex expression disables
  rows with the note instead of rewriting; `loop_always`/`route`
  stages survive a canvas load/save untouched (byte-identical YAML
  diff on those keys).
- Executable: frontend typecheck + full suite + build green.
